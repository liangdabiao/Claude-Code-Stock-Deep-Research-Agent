# 飞书单票快判助手设计稿

日期：2026-03-24

状态：已完成方案讨论，待实现

## 1. 背景

当前仓库的核心能力是股票投资尽调工作流：

- 入口是 `/stock-research`
- 强项是 8 阶段深度研究、多智能体并行、引用校验、结构化报告输出
- 产出偏重完整尽调报告，时间成本高
- 当前仓库没有现成的飞书机器人运行时、Webhook/API 服务、会话状态、任务队列或结果回推层

这意味着项目最自然的二改方向，不是继续增加研究维度，而是增加一个更轻、更高频的使用入口，把现有研究内核包装成一个在飞书里可直接使用的金融助手。

## 2. 产品定位

首版定位为：

`飞书里的单票快判助手`

目标用户：

- 个人投资者
- 需要快速判断一只股票是否值得继续研究的人

核心任务：

- 用户发出股票名或代码后，30 秒内得到一个可行动的初步判断
- 用户在觉得有价值时，再一键触发完整深研
- 完整深研完成后，继续围绕该报告追问

这不是一个泛财经机器人，也不是交易助手。

## 3. 设计原则

### 3.1 保持专注

首版只解决一个问题：

`这只股票现在值不值得继续研究`

### 3.2 先结论，后深挖

飞书场景下，用户的第一需求不是问卷式澄清，而是先看到一个可信的快判结果。

### 3.3 复用现有研究资产

现有深研框架继续作为“重路径”使用，不重写整套研究逻辑。

### 3.4 输出模板固定

飞书首屏必须高度结构化，避免长文、开放式输出和风格漂移。

## 4. 目标与非目标

### 4.1 首版目标

- 支持 A 股、港股、美股的单票输入
- 在飞书中提供单票快判卡片
- 支持从快判卡片一键进入完整深研
- 深研完成后回推摘要与报告入口
- 支持基于已生成报告进行简短追问

### 4.2 明确不做

- 不做泛财经新闻机器人
- 不做基金、债券、期货、加密等多资产扩展
- 不做技术分析、择时、交易信号、买卖点提示
- 不做复杂投顾画像或长期用户画像系统
- 不在首版中加入双票对比、自选股观察列表、财报自动推送

## 5. 目标用户与核心场景

### 5.1 目标用户

- 有基本股票认知的个人投资者
- 会在飞书里随手提出一个问题，但不愿意经历复杂配置过程

### 5.2 核心场景

场景 A：单票初筛

- 用户输入：`腾讯值得继续研究吗`
- 系统输出快判卡片

场景 B：从快判进入深研

- 用户点击 `生成完整深研`
- 系统补问极少参数
- 后台异步生成完整尽调报告

场景 C：围绕报告追问

- 用户输入：`这份报告里最大的风险是什么`
- 系统优先基于已有报告回答

## 6. MVP 边界

首版 MVP 只包含 3 个动作：

### 6.1 动作一：单票快判

输入：

- 股票代码
- 公司名称

输出：

- 一张飞书卡片

### 6.2 动作二：生成完整深研

从快判卡片进入，系统只补问以下参数：

- 投资风格：价值 / 成长 / 红利
- 持有周期：中期 / 长期
- 关注重点：生意质量 / 财务质量 / 估值

### 6.3 动作三：基于已有报告追问

只回答和当前报告直接相关的问题，不扩展成泛化金融百科。

## 7. 用户体验设计

### 7.1 首轮交互

用户只需发一条文本消息：

- `腾讯`
- `00700.HK`
- `腾讯值得继续研究吗`

系统默认直接进入快判流程，不先做多轮提问。

### 7.2 快判卡片模板

卡片字段固定为：

- 标的名称与代码
- 快判结论
- 估值温度
- 3 条核心依据
- 2 条主要风险
- 1 个下一步动作建议
- 按钮：`生成完整深研`
- 免责声明

### 7.3 快判结论枚举

- 值得继续研究
- 可观察但暂不优先
- 风险较高，暂不建议优先看

### 7.4 估值温度枚举

- 偏低
- 中性
- 偏高

### 7.5 深研补问设计

点击 `生成完整深研` 后，最多只进行一次轻量补问，且参数数目不超过 3 个。

设计目的：

- 保留个性化研究入口
- 避免在飞书中变成问卷

### 7.6 深研完成后的回推

完成后回推一张摘要卡片，包含：

- 标的
- 研究结论摘要
- 核心论点
- 主要风险
- 报告入口

## 8. 系统架构

推荐采用“双通道架构”：

- 快路径：面向飞书首轮交互的 `Quick Judge Engine`
- 重路径：复用现有研究内核的 `Deep Research Orchestrator`

### 8.1 组件划分

### Feishu Bot Gateway

职责：

- 接收消息事件
- 验签
- 去重
- 解析用户和会话上下文
- 回传卡片

### Intent Router

只识别以下意图：

- 单票快判
- 生成完整深研
- 基于已有报告追问

其他问题统一收敛回复，不扩展成泛财经开放问答。

### Symbol Resolver

职责：

- 解析股票代码、简称、公司名
- 统一映射到内部标的 ID
- 只有在存在明显歧义时才追问

### Quick Judge Engine

职责：

- 在短时间内生成首轮判断
- 输出固定模板结果
- 为深研转化提供入口

### Deep Research Orchestrator

职责：

- 接收深研任务
- 组织最小参数补问
- 调用现有股票深研框架
- 维护任务状态

### Research Worker

职责：

- 异步执行完整尽调
- 复用现有 8 阶段研究方法与报告结构

### Report Store

职责：

- 存储快判摘要
- 存储深研报告
- 存储任务状态与元数据
- 为后续追问提供上下文

### Push Service

职责：

- 推送受理状态
- 推送研究完成状态
- 推送报告摘要卡片

### Guardrail Layer

职责：

- 统一免责声明
- 过滤交易建议式输出
- 限制不支持的资产与问题类型

### 8.2 推荐目录结构

建议把运行时系统与研究资产分离：

```text
apps/
  feishu-bot/
  research-worker/
packages/
  research-core/
storage/
  reports/
```

当前仓库里的研究文档、命令和技能继续保留为研究内核参考与复用来源。

## 9. 快判引擎设计

快判引擎的职责不是生成完整研究，而是快速形成“是否值得继续研究”的初筛结论。

### 9.1 输入

- 标的 ID
- 基础公司信息
- 基础估值与财务信息
- 最近的重要公开信息
- 已存在的历史研究资产（若有）

### 9.2 输出

- 快判结论
- 估值温度
- 核心依据
- 主要风险
- 建议动作

### 9.3 评估维度

- 生意质量是否足够清晰
- 财务质量是否存在明显红旗
- 当前估值是否具备继续研究价值
- 是否存在需要立刻注意的风险事件

### 9.4 快判不做的事

- 不输出目标价
- 不给出买卖建议
- 不预测短期股价
- 不展开完整多空论证

## 10. 深研路径设计

深研路径延续当前项目的核心能力，但对飞书场景做以下约束：

- 深研必须异步
- 深研前只收集最少参数
- 深研输出继续采用结构化报告
- 深研结果必须能被后续问答复用

### 10.1 与现有仓库能力的关系

可复用内容：

- 股票研究方法论
- 8 阶段研究结构
- 多智能体思路
- 引用验证要求
- 标准化报告组织方式

需要新建的内容：

- 机器人入口
- 任务队列
- 状态持久化
- 飞书卡片回推
- 会话与报告索引

## 11. 数据与状态设计

首版不做复杂用户画像，只保留与当前会话直接相关的状态。

### 11.1 核心实体

- `conversation`
- `user_request`
- `research_job`
- `report`
- `symbol`

### 11.2 最小状态

- 当前讨论的标的
- 最近一次快判结果
- 深研任务状态
- 最近一次报告 ID

### 11.3 缓存策略

可缓存内容：

- 标的解析结果
- 快判摘要
- 已完成报告摘要

缓存目的：

- 降低重复查询成本
- 提高飞书首轮响应速度

## 12. 输出边界与风控

### 12.1 必须保留的边界

- 所有结论仅基于公开信息
- 不构成投资建议
- 不提供交易指令
- 不提供具体买入卖出点

### 12.2 回复原则

- 区分事实与判断
- 用少量可验证依据支撑结论
- 明确指出不确定性
- 当问题超出首版范围时，收敛而不是扩展

## 13. 成功指标

首版优先关注以下指标：

- 快判首响应时间
- 快判后点击 `生成完整深研` 的比例
- 深研完成率
- 深研完成后的追问率
- 同一用户的重复使用率

## 14. 迭代路线

### 第 1 阶段：飞书快判入口

- 建立飞书机器人接入
- 打通单票快判链路
- 固化卡片模板

### 第 2 阶段：异步深研

- 建立任务编排与状态回推
- 复用现有研究框架生成完整报告

### 第 3 阶段：报告追问

- 基于已生成报告做简短问答
- 优先复用已有结论，不重复跑全量深研

### 第 4 阶段：第二阶段候选扩展

仅在首版验证成功后，再考虑：

- 双票对比
- 自选股观察列表
- 财报事件后的增量更新

## 15. 关键风险

### 风险 1：快判质量不稳定

如果首轮快判模糊、空泛或结论摇摆，用户不会继续点击深研。

### 风险 2：飞书首轮交互过重

如果第一轮补问太多，飞书用户会流失。

### 风险 3：把产品做成泛财经机器人

一旦边界失控，研发成本会迅速上升，且削弱“单票快判助手”的定位。

### 风险 4：深研结果不可复用

如果报告生成后不能承接后续追问，系统就会退化为一次性工具。

## 16. 为什么这个方向优先

这个方向优先的原因不是“功能更容易做”，而是用户最容易感知价值：

- 用户只需输入一只股票
- 系统立刻给出一个明确判断
- 用户自然产生下一步动作
- 当前仓库已有的深研能力可以作为高价值升级路径

这条链路清晰、聚焦，并且最大化复用了现有项目的优势。

## 17. 最终结论

首版推荐方案为：

`飞书里的单票快判助手`

核心路径为：

`一句话输入 -> 单票快判卡片 -> 一键完整深研 -> 围绕报告追问`

这是当前项目最合理、最聚焦、最容易被用户感知到价值的二改方向。
